## 1. 项目概述

### 1.1 项目背景

随着大语言模型(LLM)在企业场景的普及,通用模型无法覆盖企业私域知识,且存在幻觉问题。火山方舟推出的 RAG 知识库方案,通过"文档上传 → 解析切片 → 向量化 → 检索 → 大模型问答"的链路,实现了基于企业专属数据的精准问答。

本项目旨在自研一套轻量化、可私有化部署的知识库系统 **Easy-Knowledge**,对标火山方舟知识库的核心能力,同时支持接入多种大模型与向量模型,便于企业在内网环境中独立运行。

### 1.2 项目目标

| 类别 | 目标 |
|------|------|
| 核心能力 | 实现文档上传、解析切片、向量化、混合检索、RAG 问答全链路 |
| 易用性 | 提供 Web 控制台,可视化创建知识库、管理文档、调试问答 |
| 可扩展性 | 模型层抽象,支持豆包/OpenAI/本地模型可插拔切换 |
| 私有化 | 支持纯本地部署(本地向量库、本地对象存储、本地大模型) |

### 1.3 项目范围

**包含:**
- 知识库 CRUD 与文档管理
- 多格式文档解析与切片策略配置
- 向量化(Embedding)与混合检索(稠密 + 稀疏)
- RAG 问答与会话管理
- 用户、权限、操作日志
- Web 控制台 + Electron 桌面端
- 本地化部署方案

**不包含:**
- 模型训练 / 微调
- 复杂工作流编排(如扣子式节点编排,留作 v2 规划)
- 多租户 SaaS 计费体系

### 1.4 术语表

| 术语 | 说明 |
|------|------|
| RAG | Retrieval-Augmented Generation,检索增强生成 |
| Embedding | 将文本映射为高维向量 |
| 切片(Chunk) | 将长文档按策略切分为可检索的小段落 |
| 混合检索 | 稠密向量(语义) + 稀疏向量(关键词)联合检索 |
| Rerank | 对初检结果二次重排,提升相关性 |
| Collection | 知识库集合,对应一个独立的知识库 |
| Slice / Chunk | 切片,知识库的最小检索单元 |

## 2. 需求分析

### 2.1 用户角色

| 角色 | 权限 |
|------|------|
| 管理员 | 管理用户、配置模型、管理所有知识库 |
| 知识库用户 | 创建/管理自有知识库、上传文档、配置切片策略、调用知识库问答 API、查看授权知识库问答页面问答 |

### 2.2 功能性需求

#### 2.2.1 知识库管理
- 创建知识库(名称、描述、数据类型、标签策略、检索参数)
- 编辑、删除、列表查询、详情查看

#### 2.2.2 文档管理
- 上传方式:本地上传(对象存储导入、公开 URL 抓取留作 v2)
- 支持格式:`txt`、`md`、`doc/docx`、`pdf`(含扫描件)、`pptx`、`csv`、`xlsx`、`jsonl`、`png/jpg`(OCR)
- 文档状态:待解析、解析中、解析失败、已就绪
- 文档删除、重新解析、切片详情查看
- 文档标签与元数据(用于过滤检索)

#### 2.2.3 解析与切片
- 解析模式:通用解析(含表格/图片)、极速解析(纯文本)
- 切片策略:
  - 固定长度切片(可配置最大长度,默认 2000)
  - 自定义分隔符切片
  - 合并邻近短文本
  - PPT/PDF 整页切片
- 图片 OCR:对 PDF/Word 内嵌图片进行文字识别并独立切片
- 文档摘要:可选开启,AI 自动生成切片摘要

#### 2.2.4 向量化(Embedding)
- 支持模型:
  - 豆包 Embedding / Embedding 多功能版(混合检索)
  - OpenAI text-embedding-3
  - 本地 bge-m3 等
- 维度配置(可选降维)
- 增量向量化(文档更新仅重算变更切片)

#### 2.2.5 检索
- 混合检索:稠密向量 + 稀疏向量(BM25 / 稀疏向量)加权融合
- 标量过滤:按标签、元数据字段过滤
- Rerank:可选接入豆包 Rerank / bge-reranker 重排
- 返回参数:TopK、相似度分数、来源文档、切片内容、图片附件链接

#### 2.2.6 RAG 问答
- 单轮问答 / 多轮会话
- 知识库选择(单库 / 多库)
- 引用标注:回答中标注引用切片来源
- 流式输出(SSE)
- Prompt 模板可配置(System Prompt、引用拼接模板)
- 模型选择:豆包 / OpenAI / 本地模型

#### 2.2.7 用户与权限
- 用户注册、登录(JWT)
- 角色与权限(RBAC)
- 知识库级权限(私有 / 共享)
- 操作日志审计

#### 2.2.8 系统配置
- 模型供应商配置(API Key、Base URL、模型列表)
- 向量库配置
- 对象存储配置
- 邮件通知(可选)

### 2.3 非功能性需求

| 维度 | 指标 |
|------|------|
| 性能 | 单文档(10MB)解析 < 30s;检索 P95 < 500ms(10 万切片规模) |
| 并发 | 默认支持 50 并发问答,可通过 CU 配置横向扩展 |
| 可用性 | 单机部署 99%,集群部署 99.9% |
| 安全 | 传输 HTTPS、落盘加密、API Key 加密存储、内容安全审核(可选) |
| 可维护性 | 模块化设计,模型层可插拔 |
| 兼容性 | 主流浏览器最新版 |
| 国际化 | 预留 i18n,默认中文 |

### 3.3 后端目录结构约定

采用「Feature-based Module + 全局 common/」结构,模块自包含、全局共享项放 `common/`。

```
server/src/
├── common/                  # 🌐 全局共享(跨模块复用)
│   ├── prisma/              # ✅ 已有:全局数据库访问(@Global)
│   ├── dto/                 # 通用 DTO(分页 / 统一响应 / 通用枚举)
│   │   ├── pagination.dto.ts

│   ├── audit/               # 后续:审计日志

│
├── app.module.ts            # 根模块(只做 imports 聚合)

```

#### 划分原则

| 场景 | 放哪里 | 举例 |
|---|---|---|
| 只被一个模块使用 | `modules/xxx/` 内部 | `auth/dto/login.dto.ts` |
| 被 ≥2 个模块复用 | `common/` 对应子目录 | `common/dto/pagination.dto.ts` |
| 需要 DI 的服务 | 独立模块或 `common/services/` | `MailService`(需 ConfigService) |
| 纯函数工具(无 DI) | `common/utils/` | `bcrypt.util.ts`、`dayjs.util.ts` |

#### 通用 DTO 复用示例

通用 DTO 放 `common/dto/`,业务模块继承扩展:

```ts
// common/dto/pagination.dto.ts
export class PaginationDto {
  @IsInt() @Min(1) page: number = 1;
  @IsInt() @Min(1) @Max(100) pageSize: number = 20;
  @IsOptional() keyword?: string;
  @IsOptional() sort?: string;
}

// modules/user/dto/query-user.dto.ts
export class QueryUserDto extends PaginationDto {
  @IsOptional() role?: string;       // 用户专属筛选字段
  @IsOptional() status?: string;
}
```

#### 何时创建 common/ 子目录

**按需创建,不预建空目录。** 当下一个模块需要时再建:
- 开发用户管理时 → 建 `common/dto/` + `common/decorators/` + `common/guards/`
- 接入 Qdrant 时 → 建 `common/qdrant/`(全局 Qdrant 客户端)
- 接入 MinIO 时 → 建 `common/minio/`

### 3.4 核心流程

#### 文档入库流程
```
用户上传 → 存 MinIO → 写 document 记录(待解析) → 投递 parser 队列
   → 解析+切片 → 写 chunk 记录 → 投递 embedding 队列
   → 向量化 → 写入向量库 → 更新 document 状态(已就绪)
```

#### 问答流程
```
用户提问 → Query 改写(可选) → Embedding → 混合检索 TopK
   → Rerank → 拼 Prompt(引用切片) → LLM 流式生成 → 标注引用 → 返回
```

| 用途 | 适配模型 | 是否免费 |
|------|----------|----------|
| Embedding(默认推荐) | **bge-m3**(本地,稠密+稀疏混合) | ✅ 开源免费 |

| Rerank(默认推荐) | **bge-reranker-v2-m3**(本地) | ✅ 开源免费 |
| Rerank(商业) | Doubao Rerank | ❌ 按量付费 |
| LLM 问答 | Doubao-seed、DeepSeek、OpenAI GPT | ❌ 按量付费 |
| LLM 问答(本地) | Ollama 本地模型(Qwen/DeepSeek 等) | ✅ 开源免费 |
| OCR | PaddleOCR(本地) / 豆包视觉模型 | PaddleOCR 免费 |

**本地模型部署方式**(Embedding / Rerank):
- **Infinity**(BGE 官方推理服务,推荐):提供 OpenAI 兼容 API
- **Text Embeddings Inference**(HuggingFace):轻量
- **Ollama**:`ollama pull bge-m3`(最简)

> 说明:bge-m3 一个模型可同时产出稠密向量和稀疏向量,天然匹配本文档的"混合检索"设计,无需额外部署 BM25 服务。

## 5. 详细模块设计

### 5.1 知识库模块(KnowledgeService)

**职责**:知识库的创建、配置、生命周期管理。

**核心字段**:
- `name`、`description`
- `dataType`:枚举 `unstructured` | `structured`
- `embeddingModelId`:关联模型配置
- `embeddingDimension`
- `retrievalConfig`:`{ topK, denseWeight, sparseWeight, rerankModelId, rerankTopN }`
- `parsePolicy`:默认解析策略(解析模式、切片长度、是否 OCR、是否摘要)
- `tags`:可用标签 schema
- `cpuQuota`:检索并发配额(限流用)

**接口**:`create` / `update` / `delete` / `list` / `getDetail` / `testRetrieve`

### 5.2 文档模块(DocumentService)

**职责**:文档上传、状态机、元数据管理。

**状态机**:
```
pending → parsing → embedding → ready
   │         │         │
   └─────────┴─────────┴──→ failed(记录错误原因)
```

**核心字段**:
- `knowledgeId`
- `fileName`、`fileSize`、`mimeType`、`objectKey`(MinIO 路径)
- `source`:`local`(后续扩展 `tos` | `url` | `feishu`)
- `status`、`errorMsg`
- `tags`(JSON)、`metadata`(JSON,结构化字段)
- `parsePolicy`(可覆盖知识库默认)
- `chunkCount`、`tokenCount`

**接口**:`upload` / `uploadByUrl` / `reparse` / `delete` / `list` / `getChunks`

### 5.3 解析切片模块(ParserService)

**职责**:异步消费队列,对文档解析切片。

**子模块**:
- `LoaderRegistry`:按 MIME 类型路由加载器
  - PDF:`pdf-parse` + 扫描件 OCR
  - Word:`mammoth`
  - PPT:`pptxtojson`
  - Markdown:`LangChain MarkdownTextSplitter`
  - 结构化:`csv-parse` / `xlsx`
  - 图片:`PaddleOCR` 子进程
- `ChunkStrategy`:
  - `FixedLengthChunker`:固定长度,可配置 overlap
  - `DelimiterChunker`:自定义分隔符
  - `PageChunker`:整页切片(PPT/横版 PDF)
  - `MergeShortChunker`:合并邻近短文本
- `SummaryGenerator`:可选,调用 LLM 生成切片摘要

**输出**:切片数组 `[{ content, page, position, images[], summary? }]`

### 5.4 向量化模块(EmbeddingService)

**职责**:将切片文本转为向量,写入向量库。

**适配器模式**:
```ts
interface EmbeddingProvider {
  name: string;
  embed(texts: string[]): Promise<number[][]>;
  dimension: number;
  sparse?: boolean; // 是否同时返回稀疏向量
}
```

**实现**:`DoubaoEmbeddingProvider`、`OpenAIEmbeddingProvider`、`LocalBgeProvider`

**特性**:
- 批量调用(默认 32 条/批)
- 限流与重试
- 增量计算(文档更新仅重算变更切片)
- 失败入死信队列

### 5.5 检索模块(RetrieveService)

**职责**:混合检索 + 重排。

**流程**:
1. Query 预处理(改写、扩展关键词)
2. 并行执行:
   - 稠密检索:向量库 `search(denseVector, topK * 2)`
   - 稀疏检索:BM25 / 稀疏向量 `search(sparseVector, topK * 2)`
   - 标量过滤:按 `knowledgeId`、`tags`、`metadata` 过滤
3. 融合:RRF(Reciprocal Rank Fusion)或加权打分
4. Rerank(可选):取 Top N 送入 Rerank 模型重排
5. 返回:`[{ chunkId, content, score, docId, docName, page }]`

**适配器**:
```ts
interface VectorStore {
  upsert(vectors, metas): Promise<void>;
  search(vector, filter, topK): Promise<Hit[]>;
  deleteByDoc(docId): Promise<void>;
}
```
**实现**:`QdrantVectorStore`

### 5.6 问答模块(ChatService)

**职责**:RAG 问答、会话管理、流式输出。

**核心逻辑**:
1. 接收用户问题 + 会话历史 + 知识库 ID 列表
2. 调用 `RetrieveService` 获取引用切片
3. 按 Prompt 模板拼接:
   ```
   [System] 你是知识库助手,优先依据【参考资料】回答...
   [Context] 切片1(docA, p3):...
   [Context] 切片2(docB, p1):...
   [History] ...
   [User] {question}
   ```
4. 调用 LLM(Vercel AI SDK `streamText`)流式输出
5. 回答完成后,后处理插入引用标注 `[1]` `[2]`
6. 持久化会话消息,关联引用切片

**Prompt 模板可配置**,支持变量:`{context}`、`{history}`、`{question}`、`{datetime}`。

### 5.7 用户与权限模块

- JWT 访问令牌(2h)+ 刷新令牌(7d)
- RBAC:角色 → 权限点 → 资源
- 知识库权限:`owner` / `editor` / `viewer`
- 接口级 Guard:`@Roles('admin')`、`@KnowledgeAccess('viewer')`

### 5.8 配置与审计模块

- `SystemConfig`:模型供应商、向量库、存储等连接信息,加密存储敏感字段
- `AuditLog`:操作人、动作、资源、IP、时间、结果,支持查询导出

### 6.3 向量库 Schema(Qdrant)

```
Collection: knowledge_{knowledgeId}
  Vectors:
    - dense  (FLOAT_VECTOR, size=embeddingDimension)
    - sparse (SPARSE_VECTOR)
  Payload (可过滤字段):
    - document_id:   keyword
    - chunk_id:      keyword
    - content:       text
    - page:          integer
    - tags:          keyword[]
    - metadata:      object
Indexes:
    - dense:  HNSW (M=16, ef_construct=200, distance=Cosine)
    - sparse: SPARSE_INDEX (index_type=sparse_inverted, compression=None)
    - payload: document_id (keyword)、tags (keyword 数组)、page (integer)
```

**混合检索调用**(Qdrant `search_batch` 一次请求):
1. `search(dense vector, collection, limit=topK*2)` —— 稠密语义召回
2. `search(sparse vector, collection, limit=topK*2, using=sparse)` —— 稀疏关键词召回
3. 融合:RRF 加权后送入 Rerank

## 7. 接口设计

### 7.1 通用约定

- Base URL:`/api`
- 鉴权:`Authorization: Bearer <jwt>`
- 响应统一格式(所有接口均返回此结构,含异常):
  ```json
  {
    "code": 200,
    "message": "ok",
    "data": { ... }
  }
  ```
  - `code`:HTTP 状态码语义枚举(见下表),成功固定 `200`
  - `message`:人类可读的提示信息
  - `data`:业务数据,失败时为 `null`
- 状态码枚举:

  | code | 含义 | 触发场景 |
  |---|---|---|
  | 200 | 成功 | 正常请求 |
  | 400 | 参数错误 | 请求格式不对 / 缺字段 |
  | 401 | 未登录 | token 失效 / 未携带 |
  | 403 | 无权限 | 已登录但无操作权限 |
  | 404 | 资源不存在 | 查不到记录 |
  | 409 | 资源冲突 | 用户名/名称重复 |
  | 422 | 语义错误 | class-validator 校验失败 |
  | 429 | 限流 | 超出频率限制 |
  | 500 | 服务器错误 | 未捕获异常 |
  | 502 | 上游错误 | 模型/向量库不可达 |
  | 503 | 服务不可用 | 维护中 / 依赖未就绪 |

- 分页:`?page=1&pageSize=20`,返回 `{ list, total, page, pageSize }`
- 实现位置:
  - 响应拦截器:[transform.interceptor.ts](file:///f:/dzcoder/easy-knowledge/server/src/common/interceptors/transform.interceptor.ts)(自动包装成功响应)
  - 异常过滤器:[http-exception.filter.ts](file:///f:/dzcoder/easy-knowledge/server/src/common/filters/http-exception.filter.ts)(统一异常格式)
  - 响应类型:[api-response.dto.ts](file:///f:/dzcoder/easy-knowledge/server/src/common/dto/api-response.dto.ts)(`ResponseCode` 枚举 + `ApiResponse<T>`)

| `field.action` | 尾部按钮(搜索图标/发送,可选) |

**状态表现**:
- 正常:浅底 + 细边框
- focus: `border-color` 切 `--ring`,不换底色(**不用亮色填充**)
- error:边框切 `--destructive`,helper 文字同色
- disabled:背景降为 `--card`,字 `--muted-foreground`,无阴影

**特殊形态 Embedded(Bar)**:无外边框,仅 `--card` 背景 + 左右 12px pad,用于聊天输入框组合。

#### 8.4.4 Badge · 徽标

| 解剖 | 说明 |
|---|---|
| `badge.root` | inline-flex,min-height 32px,圆角 16px,字重 600,12px |
| `badge.label` | 截断省略 |
| `badge.icon` | 与文字 6px 间距(可选) |

**三种语气**:
- `filled`:`--primary` + 反色字 + shadow-xs(高优先级状态)
- `muted`:`--muted` + 正常字(次级说明、标签)
- `outline`:`--popover` + `--border`(最低优先级,多标签列表)

禁用态一律降为饱和度下一档。

#### 8.4.5 Chat Bubble · 聊天气泡(知识库 RAG 问答核心)

| 解剖 | 说明 |
|---|---|
| `thread.root` | 整串对话容器, 圆角 20px + border + shadow-sm |
| `message.row` | 行布局,assistant 左对齐,user 右对齐 |
| `message.avatar` | 28x28,圆角全圆,assistant 用品牌图标,user 用用户头像(可选) |
| `message.bubble` | max-width 640px,圆角 18px,内边距 14px~16px |
| `message.meta` | 11px/500/字距 0.01em,位于气泡上方或下方 |

**两种身份**:

| 身份 | 背景 | 文字 | 行高 |
|---|---|---|---|
| `assistant` | `--popover` + 1px `--border` | `--card-foreground` | **Lora 14px/1.6**(长文阅读优先) |
| `user` | `--primary` | `--primary-foreground` | Poppins 14px/1.5(紧凑) |

RAG 专用扩展:
- 引用上标数字:`<sup>` 样式对齐 badge muted,可悬浮显示来源(`docName + page`)
- 代码块:`--font-mono` + `--card` 背景 + 16px 圆角内嵌
- 流式渲染:保留换行,字出现后使用 `.opacity-100` 平滑进入

#### 8.4.6 Navigation · 导航

| 解剖 | 说明 |
|---|---|
| `nav.root` | 侧栏 rail(宽 236px + padding 14px) + 顶栏 tabs + 移动端 bottom-nav |
| `nav.brand` | 11px/600/全大写/字距 0.14em,`--sidebar-foreground` |
| `nav.sectionLabel` | kicker 同风格,分块标题(可选) |
| `nav.item` | 13px/600,圆角 8px(= radius - 8px),padding 12~13px |
| `nav.activeIndicator` | 不使用独立颜色线,直接用 item active 的 `popover` 背景 + shadow-xs |

**状态色调**(非常克制):
- 默认:`--sidebar-foreground`,背景透明
- hover:`--sidebar-accent`(亮模式下是 `#E9E6DC`)
- active:`--popover` 背景 + 与其它色融合,不使用饱和彩色条

禁用态:`--muted-foreground` + 透明背景。

#### 8.4.7 跨组件通用规则

1. **高度对齐**:`同层级的 button 与 input 高度必须完全一致`(默认都是 44px)——这是"克制整齐感"的关键细节
2. **Focus Ring**:全部统一 `outline:2px solid var(--ring); outline-offset:2px`
3. **过渡曲线**:全部 `transition: * .16s ease`,不使用 cubic-bezier 花活
4. **可访问性**:
   - 所有交互元素有可聚焦态(button/input/nav-item/badge 均已提供)
   - 禁用态必须带 `aria-disabled` 或 `disabled` 属性
   - 颜色对比度:正文至少 WCAG AA(4.5:1),大字 AA(3:1)
5. **动效**:仅 hover / active / focus 微动作(translateY -1px / 阴影升级)。页面级切换用 Vue `<Transition>` 的 `opacity 150ms`,不入场缩放弹跳
6. **保存反馈**(用户偏好):所有表单保存按钮成功/失败用 `ElMessage`(`success` 打 `--success` 绿,`error` 打 `--destructive` 红),且按钮在请求期间 `loading + disabled`

## 11. 风险评估

| 风险 | 等级 | 应对 |
|------|------|------|
| 大文档解析耗时长 / OOM | 高 | 队列异步 + 流式解析 + 分块读取 |
| Qdrant 单节点性能瓶颈 | 中 | 集群分片 + 提前压测;必要时迁 Milvus(接口已抽象) |
| 混合检索效果不达预期 | 中 | 预留 Rerank 接入点 + 评测集回归 |
| 本地大模型效果弱 | 中 | 默认支持云模型,本地作为兜底 |
| OCR 依赖部署复杂 | 中 | 抽象 OCRProvider,可切豆包视觉模型 |
| 模型 API 限流 | 中 | 队列 + 令牌桶限流 + 重试退避 |
| 安全:文档泄露 | 高 | 落盘加密 + 权限隔离 + 审计日志 |
